# iPhone Price Bot 🇺🇦

Telegram-бот, який кожні 30 хвилин переглядає ціни на iPhone і надсилає найвигідніші пропозиції.

| Джерело | Що дає | Як читається (перевірено наживо, листопад 2026) |
|---|---|---|
| **Hotline.ua** | мінімальна ціна серед ~50–90 магазинів (Allo, Comfy, Moyo, Brain, iSpace, Stylus, Touch…) | JSON-LD `AggregateOffer` на сторінці товару |
| **Rozetka** | ціни Rozetka і продавців її маркетплейсу (Rozetka на Hotline немає) | JSON API сайту, поле `state`: new / used / refurbished |
| **Prom.ua** | сотні дрібних магазинів, часто сірий імпорт | JSON-LD на сторінці пошуку, стан — за заголовком |
| **OLX.ua** | приватні оголошення, нові й вживані | JSON API сайту, поля стану, пам'яті, батареї |

Запускається безкоштовно в **GitHub Actions**, без сервера. Не має runtime-залежностей: потрібен лише Node.js ≥ 22.18, бо він виконує TypeScript напряму.

## Яку пропозицію бот вважає вигідною

| | Як працює | Приклад повідомлення |
|---|---|---|
| 🔥 **Нижче ринку** | Ціна на ≥20% нижча за медіану такої ж моделі (модель + пам'ять + стан) за останні 7 днів | `iphone 15 128gb (вживане)` 14 500 ₴ (медіана 19 500 ₴, −26%) · стан: дуже добрий · АКБ 90–94% |
| 🎯 **Твій поріг** | Ціна ≤ `maxPrice` із правила у `watch` | `iphone 16 pro 256gb (вживане)` 25 900 ₴ · твій поріг ≤ 26000 |
| 📉 **Новий мінімум** | Мінімальна ціна на Hotline впала на ≥3% нижче за мінімум за 30 днів | `iphone 15 128gb (нове)` 22 900 ₴ (було 23 800 ₴, −4%) |
| 🏆 **Найкраща ціна** | Лише для моделей із `filter.models`: найнижча ціна серед усіх джерел упала на ≥2% нижче за мінімум за 30 днів | `iphone 17 pro 256gb (нове)` 48 900 ₴ (мін. за 30 днів 49 900 ₴, −2%) · prom, Магазин |
| 🔥 **Дешевше за магазини** | Для нових: оголошення на ≥5% дешевше за найдешевший магазин на Hotline | `iphone 17 pro 256gb (нове)` 50 700 ₴ (найдешевший магазин на Hotline 54 000 ₴, −6%) |

**eSIM-версії** (американські, без фізичної SIM) зазвичай на 8–10% дешевші. За замовчуванням бот рахує їх окремим ринком (`iphone 17 pro 256gb eSIM`); з `filter.ignoreEsim: true` — разом із SIM-версіями, і тоді «найкраща ціна» — найдешевший телефон незалежно від типу SIM. Тип SIM усе одно видно в повідомленні.

Від шахраїв і сміття захищають такі фільтри:

- **Знижка понад `maxDiscount`** (45% за замовчуванням, для нових варто 30%). Таке оголошення ігнорується, бо найчастіше це шахрайство.
- **Заголовок.** Відсіюються аксесуари, запчастини, iCloud lock, MDM-профіль, bypass, копії, розбиті телефони, розстрочка.
- **«Нове», яке насправді вживане.** «Б/У», «Grade B», «27 циклів», «АКБ 97%», «Чудовий стан», «Trade-in» у заголовку роблять оголошення вживаним, навіть якщо продавець поставив «нове».
- **Стан з OLX.** Оголошення зі станом «з дефектами» або «на запчастини» пропускаються, а стан і здоров'я батареї показуються в повідомленні.
- **Неоднозначна пам'ять.** Оголошення на кшталт «128/256/512» пропускаються. Якщо пам'яті немає в заголовку, бот бере її з поля оголошення.
- **Один продавець = один голос у медіані й одне сповіщення.** Перевиставлення не зсувають «ринкову» ціну і не дублюють повідомлення.
- **Повтор лише після зниження.** Повторне сповіщення про те саме оголошення приходить, тільки якщо ціна впала ще на ≥3%.

## Швидкий старт

### 1. Створи бота

1. Відкрий у Telegram [@BotFather](https://t.me/BotFather), введи `/newbot` і скопіюй **токен**.
2. Напиши своєму новому боту будь-яке повідомлення (або додай його в групу).
3. Дізнайся свій `CHAT_ID`:
   ```bash
   BOT_TOKEN=123:abc npm run chat-id
   ```

### 2. Перевір локально

```bash
cp .env.example .env    # впиши BOT_TOKEN і CHAT_ID
npm run probe           # що бот бачить на OLX/Hotline і що розпізнає (✓/✗)
npm run dry             # повний прохід без надсилання в Telegram
npm start               # справжній прохід
```

> Перший запуск лише збирає ринкові ціни і нічого не надсилає («прогрів»). Сповіщення почнуть приходити з наступних запусків.

### 3. Запусти в GitHub Actions

1. Створи репозиторій і запуш туди проєкт.
2. **Settings → Secrets and variables → Actions → New repository secret:** додай `BOT_TOKEN` і `CHAT_ID`.
3. **Actions → iPhone price monitor → Run workflow:** спершу з галочкою `dry_run`, щоб перевірити лог.
4. Далі workflow запускатиметься сам кожні 30 хвилин.

Історія цін і список уже надісланих оголошень зберігаються в кеші Actions (`data/state.json`) між запусками.

## Налаштування: `config.json`

Зараз конфіг налаштований на **новий iPhone 17 Pro 256GB**:

```jsonc
{
  "filter": {
    "models": ["iphone 17 pro 256gb"], // лише ці моделі (покриває й eSIM); [] = усі
    "condition": "new",                // "new" | "used" | не вказано = обидва
    "ignoreEsim": true                 // SIM і eSIM — один ринок: цікавить найдешевший незалежно від SIM
  },
  "olx": {
    "queries": ["iphone 17 pro 256"], // пошукові запити
    "categoryId": 85,      // "Мобільні телефони" — відсікає аксесуари
    "pages": 2,            // сторінок по 50 оголошень на кожен запит
    "minPrice": 20000,     // нижче — ігнорувати
    "skipBusiness": false, // true = лише приватні продавці
    "skipDefects": true    // пропускати стан «з дефектами» / «на запчастини»
  },
  "rozetka": { "queries": ["apple iphone 17 pro 256gb"] },
  "prom": { "queries": ["iphone 17 pro 256gb"], "pages": 5 }, // від найдешевших; нові — далі за вживаними
  "hotline": {
    "urls": ["…/apple-iphone-17-pro-256gb-silver/", "…/apple-iphone-17-pro-256gb-esim-silver/", "…"], // 6 сторінок: 3 кольори × SIM/eSIM
    "minDrop": 0.03        // «новий мінімум» на одній сторінці = −3% від мінімуму за 30 днів
  },
  "deals": {
    "minDiscount": 0.2,         // −20% від медіани схожих оголошень = угода (для вживаних)
    "minDiscountVsShops": 0.05, // нове на −5% дешевше за найдешевший магазин на Hotline = угода
    "bestMinDrop": 0.02,        // 🏆 найкраща ціна впала на 2% нижче мінімуму за 30 днів
    "maxDiscount": 0.3,         // −30% і більше = підозріло, ігноруємо
    "minSamples": 6,            // мін. к-сть продавців для медіани
    "windowDays": 7,            // за скільки днів рахувати медіану
    "maxPerRun": 5,             // макс. угод за один прохід
    "renotifyDrop": 0.03        // повторно — лише якщо ціна впала ще на 3%
  },
  "watch": [],             // напр. { "model": "iphone 17 pro", "storage": "256gb", "condition": "new", "maxPrice": 48000 }
  "requestDelayMs": 2500   // пауза між запитами
}
```

**Щоб стежити за іншою моделлю**, зміни `filter.models`, запити в `olx` / `rozetka` / `prom` і сторінки в `hotline.urls`. Якщо очистити `filter.models`, бот працює в загальному режимі: усі iPhone, сповіщення лише «нижче медіани».

**Як вибрати `minDiscount` (загальний режим, вживані).** Живий прогін на OLX (листопад 2026, ~550 оголошень iPhone 13–17) дав такі результати: при порозі 12% угодою вважалося 48 оголошень, при 15% — 33, при 20% — 15, при 25% — 7. За замовчуванням стоїть 20%, тобто угодою стає приблизно кожне 35-те оголошення. Якщо сповіщень забагато — підніми поріг або звузь `queries` до потрібних моделей.

**Як писати правила `watch`.** Поле `model` складається з `iphone` + покоління + варіанта: `iphone 15`, `iphone 15 pro max`, `iphone 16e`, `iphone air`. Значення `storage` бувають `64gb` / `128gb` / `256gb` / `512gb` / `1tb` / `2tb`, а `condition` — `new` або `used`. Поля `storage` і `condition` необов'язкові.

**Як додати товар з Hotline.** Відкрий сторінку потрібної моделі й кольору на hotline.ua і скопіюй URL у `hotline.urls`. Потім перевір командою `npm run probe hotline`.

## Запуск на сервері або домашньому ПК

Якщо GitHub Actions не підходить (див. нижче), бот працює і як звичайний процес:

```bash
npm run loop   # прохід кожні 30 хв
```

Для VPS зручно запускати його через `pm2` або як systemd-сервіс.

## Обмеження, про які варто знати

- **OLX не має публічного API для читання оголошень.** Бот використовує той самий JSON-ендпоінт (`/api/v1/offers/`), який використовує сайт, тож структура може змінитися без попередження. Будь ласкавим: не ставь інтервал менше 15 хвилин і не збільшуй `pages` без потреби.
- **Rozetka і Prom** перевірені лише з браузера. З IP-адрес GitHub Actions вони можуть відповідати інакше. Якщо джерело не працює, бот надішле ⚠️, а решта джерел працюватиме далі.
- **Hotline розбирається з HTML.** Бот бере ціну з JSON-LD (`AggregateOffer`: lowPrice / highPrice / offerCount; перевірено наживо), а якщо його не стане — з тексту «ціни: X – Y ₴». Якщо верстка зміниться, у логах з'явиться «не вдалося знайти ціну». Зверни увагу, що мінімум на Hotline може включати **відновлені** (refurbished) пропозиції.
- **IP-адреси GitHub Actions** — це дата-центр, і сайти можуть їх блокувати (403). Якщо джерело не відповідає 6 запусків поспіль (~3 год), бот надішле в Telegram ⚠️-попередження. У такому разі запускай бота з дому або на VPS (`npm run loop`).
- **Розклад GitHub (cron)** може запізнюватися на 5–15 хвилин. У публічних репозиторіях scheduled workflows автоматично вимикаються після 60 днів без активності. У приватних витрачаються хвилини Actions: прохід кожні 30 хв ≈ 1440 запусків на місяць.
- **Кеш Actions може зникнути** (наприклад, після 7 днів без запусків). Тоді бот знову пройде «прогрів» і може повторно надіслати кілька вже відомих оголошень.

## Структура

```
src/
  main.ts            — CLI: один прохід / --loop / --dry-run
  run.ts             — пайплайн: збір → нормалізація → угоди → Telegram
  normalize.ts       — "Айфон 13 про макс 256 гб" → "iphone 13 pro max 256gb"
  deals.ts           — медіана, пороги, новий мінімум, анти-дублі
  store.ts           — стан у JSON (історія, надіслане, лічильники збоїв)
  telegram.ts        — форматування і sendMessage (з повтором на 429)
  sources/olx.ts     — OLX.ua
  sources/rozetka.ts — Rozetka (JSON API)
  sources/prom.ts    — Prom.ua (JSON-LD зі сторінки пошуку)
  sources/hotline.ts — Hotline.ua
  sources/jsonld.ts  — спільний розбір schema.org Product
scripts/
  probe.ts           — перевірка джерел і розпізнавання
  chat-id.ts         — дізнатися CHAT_ID
test/                — node:test, без мережі (фікстури й підмінений fetch)
```

**Як додати нове джерело** (Rozetka, Prom, Comfy…). Напиши функцію, яка повертає `Offer[]` (для оголошень) або `PricePoint[]` (для агрегаторів), і підключи її в `run.ts`. Найпростіше знайти потрібні дані так: DevTools → Network → Fetch/XHR, де видно запит, що повертає JSON.
